## 4. 根因判定

- **缺陷（已证，可修）：** "身份查询没有回答" 与 "身份证明为他人所有" 被当成同一件事，且后果是**永久**的。前者是传输/生命周期问题，页面可能毫发无损；后者才是必须阻断的真实冲突。
- **触发条件（未证）：** 具体子原因缺失。旧版没有记录 `failure_classes`，界面因此显示"未分类故障（CDP_PAGE_OWNERSHIP_UNCONFIRMED）"，Owner 只能找 Agent 排查——这正是本事件暴露的第二个产品缺陷。
- **不是**以下情形：不是 EXE 崩溃、不是数据库损坏、不是订单重复写入、不是三小时升级机制（当日无 `*_OUTAGE_THREE_HOURS`）。

## 6. 修复内容（不加重试时长、不禁用模块）

### 6.1 精确恢复：能重新证明归属就继续

`src/research/cdp_pages.py`：

- 新增 `NATIVE_OWNER_PROOF_ATTEMPTS = 3`。身份查询是**只读**协议调用，没回答只说明"这次没问到"，因此允许有界重证；每次重证都重新 `Target.getTargetInfo` 并比对租约里的 `targetId`。
- 新增 `_transient_ownership_proof_failure()`：只有 `TimeoutError/ConnectionError/OSError` 与 playwright 的 `TimeoutError/TargetClosedError/BrowserClosedError/WebSocketError/ConnectionClosedError/Error` 才算"没回答"。
- **`TAB_TARGET_ID_MISMATCH` 永不重试**（一次即判）：那是真实身份冲突，不是抖动。
- 页面在核对过程中关闭 → 返回 `None`（与函数入口 `page.is_closed()` 语义一致："这个页已经不归任何人"），不当作归属故障。
- 只有"三次都没回答"或"身份不匹配"才 `invalidate` 根准入并抛 `PageTargetOwnershipError`——写入保护、身份校验、独占页面语义全部保留。
- 释放（detach）失败仍按原样抛 `PageTargetCleanupError` 并作废资源，不掩盖泄漏。

### 6.2 让下一次能自己解释

- `ownership_failure_marker()`：只读异常类名 + 自有的 `[A-Z_]` 标记码，绝不复制异常原文；重证与最终失败各打一条 WARNING（`Native page ownership proof unanswered (…); re-proving` / `Native page ownership unproven: …`），日志从此能定位子原因。
- 身份不匹配、租约缺失、准入重绑三处改为 `raise error from marker`，把子原因留在异常链里；`_fault_cause_label()` 增加"消息即标记码"识别，因此界面显示 `ValueError(TAB_TARGET_ID_MISMATCH)` 这类精确标签。
- `fault_diagnostics` 新增 `CDP_PAGE_OWNERSHIP_UNCONFIRMED` / `CDP_PAGE_CREATION_UNCONFIRMED` / `CDP_PAGE_CLEANUP_UNCONFIRMED` 三条中文目录：原因、影响、可执行建议（保留 Chrome、不要新建登录环境、不要关别人的标签页、重新开始会重建并重新核对身份）。
- `FaultDiagnostic` 新增 `stage`，页面新增 **`发生阶段：`** 行（如"报价跟进（quotation）"）。
